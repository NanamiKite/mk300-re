MK300 游戏导入 25 KB 限制：补充分析

分析对象：MK300.fwsc，版本字符串 MK300_073。
用户确认：导入软件明确限制 25 KB，这一信息并非从游戏启动失败推测而来。
结论：目前可确认导入端施加了 25 KB 限制。在本固件已检查的游戏加载、
Mapper 分发和 GAME 写入边界检查路径中，未发现同样的固定上限。
尚未取得导入软件程序，因此无法确定它如何实现这个限制，也不知道设置原因。
大于 25 KB 的游戏尚未经过实机导入和运行验证。

1. 内置模拟器的格式是 NES / FC，不是 Nintendo DS。
   0x18044f74 校验外层扩展名字段 nes；0x18044fe4 校验 NES\x1a 魔数。
   从 0x18045034 开始解析 iNES / NES 2.0 头字段。

2. GAME 分区预留 135168 字节，即 132 KiB。
   extracted/container/isd_config.ini 的 GAME_LEN = 132K；
   extracted/manifest.json 的 GAME 分区 size = 135168，二者一致。
   分区大小不能直接作为 ROM 的导入上限。
   加载器还要求 40 字节外层封装。封装 +0x20 处的小端整数记录 ROM 长度，
   +0x24 处记录格式标识，ROM 数据从 +0x28 开始。
   0x18044f82..0x18044f86 要求 1 <= ROM长度 <= GAME区域大小 - 40。
   GAME 擦除和写入入口 0x180415e8 / 0x1804162a 调用共享函数 0x1803f438，
   按运行时区域大小检查边界。这些路径中未发现 25 KB 常量限制。

3. 加载器按 ROM 头部声明的 PRG / CHR 大小检查数据是否完整。
   0x18045156：PRG 字节数 = PRG bank 数 << 14，即每 bank 16384 字节。
   0x1804516a：CHR 字节数 = CHR bank 数 << 13，即每 bank 8192 字节。
   加载器同时处理 16 字节文件头和可选的 512 字节 trainer。
   这段代码没有将 PRG bank 数限制为 1。

4. Mapper 分发分支实际接受的编号：
   0, 1, 2, 3, 4, 7, 11, 66, 71, 94, 177, 180。
   0x18045286 的 12 字节表对应编号 0..11：
     0 -> 0x18045294    1 -> 0x180452ca    2 -> 0x180452da
     3 -> 0x180452ea    4 -> 0x180452fa    5 -> 拒绝
     6 -> 拒绝         7 -> 0x18045314    8..10 -> 拒绝
     11 -> 0x18045324
   0x180452a4..0x180452b4 另行匹配 66, 71, 94, 177, 180。
   存在这些实现分支，并不代表每个 Mapper 的所有变种和游戏都已通过兼容性验证。

5. 25 KB 与最简单 ROM 的体积接近，但这不能证明厂商的设计意图。
   常见小 ROM：16 字节头 + 16 KiB PRG + 8 KiB CHR = 24592 字节，
   约 24.02 KiB，向上取整显示可能为 25 KB。
   另一种 NROM 布局：16 字节头 + 32 KiB PRG + 8 KiB CHR = 40976 字节。
   Mapper 0 初始化代码（0x180b2446）将第一个 PRG bank 映射到低半区，
   最后一个 PRG bank 映射到高半区，因此能表达后一种布局。
   因而“核心只能寻址 25 KB”与这份固件的静态证据不符。
   导入端可能采用了保守的兼容性筛选，也可能沿用旧限制。具体原因仍需分析上位机。

相关证据：game_loader.asm；完整反汇编 app.disassembly.asm.gz。
